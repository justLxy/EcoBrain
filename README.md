# EcoBrain 4.0

EcoBrain 4.0 是一个面向 Minecraft 服务器的系统市场插件。玩家可以把物品卖给系统，也可以从系统库存中买回物品。和传统“管理员手工定价”或“只看库存变化自动调价”的做法不同，这一版把市场定价当成一个持续的价值发现过程：系统不会预先假定某个物品一定值多少钱，而是根据玩家的真实交易行为，逐步学习一个更可信的价格区间。

本版本的主价格链路已经从旧的 `AMM + PPO` 调参模式，切换为“纯统计学习价值发现器 + 双边报价器”。旧组件仍然保留，用于兼容历史逻辑和旧数据，但不再决定线上主价格。

## 项目动机

在很多 Minecraft 服务器里，系统商店的定价通常会走向两个极端。

第一种是人工定价。它的优点是简单直观，但维护成本极高。新物品一多，管理员很快就跟不上；一旦掉落率、玩家人数、副本收益或者服务器玩法发生变化，原来的价格又会迅速失真。

第二种是简单的自动调价模型，例如只看库存变化、成交量或者某条固定公式。它比人工维护轻松，但也更容易对短期波动过度敏感，甚至被少数玩家通过囤货、对倒、倾销等方式带偏。对于 RPG 服里带精确 NBT 的物品，这个问题尤其明显，因为“看起来差不多”的物品，在经济意义上未必真的等价。

EcoBrain 4.0 想解决的，就是这个长期存在的矛盾：既不要回到纯人工维护，也不要把价格完全交给一条容易被操控的库存曲线，而是让系统从真实交易里学习，但学得足够谨慎，尤其要对新物品、长尾物品和可疑交易保持保守。

## 研究问题

这一版更关心的，不是“插件有哪些功能按钮”，而是它试图回答哪些市场设计问题：

1. 新物品第一次进入系统市场时，应该如何给出一个保守但可继续学习的起点？
2. 什么样的交易行为可以被视为真实需求，什么样的行为更像短期操盘或自我强化？
3. 在缺乏买方证据时，为什么不能让持续卖出把一个物品“卖成高价”？
4. 系统市场为什么不该只输出一个单点价格，而应该同时给出 `mid`、`bid` 和 `ask`？
5. 对于精确 NBT 的物品，如何做到真正的“一物一市”，而不是用模板化归并抹平差异？

## 核心思路

EcoBrain 4.0 的核心思路可以概括为一句话：**先做价值发现，再做双边报价。**

具体来说，每个完整序列化后的 `item_hash` 都拥有自己独立的市场状态。系统不会先把物品按“材质”“名称”或“类别”粗暴合并，而是默认每个精确身份都是独立标的。这样做的代价是，长尾物品更难快速学出稳定价格；但它带来的好处也非常明确：不会把 RPG 服中真正不同的装备、材料、词条或 NBT 物品错误地混在一起。

在这个前提下，系统会为每个物品维护一组慢变量，用来描述它当前大致值多少钱、这个判断有多不确定、市场处在哪个成熟阶段、近期交易是否存在操盘迹象，以及库存里到底有多少可以被视为“可信流动性”。这些状态共同决定系统如何报出买价和卖价。

## 创新点

相较于传统系统市场，这套方案有几个比较关键的创新点。

1. **把“价值中心”和“成交报价”拆开。** 系统不再试图维护一个唯一的 `currentPrice`，而是先估计一个统计意义上的中枢价格，再根据库存压力、风险和不确定性展开成买卖双边报价。
2. **把“库存”和“流动性”拆开。** 不是所有库存都应该被当成真实市场深度。EcoBrain 4.0 会把物理库存压缩成 `trusted_float`，只把和近期真实交易活跃度相匹配的部分视为可信流动性。
3. **把“成交量”和“可信证据”拆开。** 同样是 100 个成交，分散发生在很多玩家之间，和集中发生在两三个人之间，经济含义完全不同。系统会显式统计独立买家数、独立卖家数、前两名玩家流量占比、短时回转率等行为特征，而不是只看聚合总量。
4. **把新物品和成熟物品区别对待。** 对未知物品，系统默认宽价差、高不确定性，并且禁止单靠卖出把价格抬高；对成熟物品，系统才逐步收紧价差，让市场更接近常规做市逻辑。
5. **把反操盘逻辑放进主链路。** 反操盘不再是外围补丁，而是直接影响证据权重、阶段晋级、价差宽度，以及是否允许继续向上修正价格。

## 算法细节

### 1. 价格状态如何表示

系统在对数价格空间里维护每个物品的后验分布，用两个核心量来描述它：

- `mu_log_price`：当前对“合理价格中心”的估计。
- `sigma_log_price`：当前对这个估计的不确定性。

新物品进入市场时，会从一个中性锚点出发：默认 `mu = ln(100)`，`sigma = 2.3`。这里的 `100` 不是系统承诺的真实收购价，而只是“先把物品放在一个中性位置观察”的起点。高 `sigma` 的含义也很明确：系统承认这个物品出现了，但对它到底值多少钱还没有把握。

### 2. 交易证据如何更新价格

每次真实交易发生后，系统会把成交单价转换到对数空间，作为一条新的观察证据，与当前后验做一次精度加权融合。直观地说，证据越可信、交易量越大，更新幅度越大；已有判断越稳定，单笔交易就越难把价格拉得太远。

不过，并不是所有交易都被一视同仁。EcoBrain 4.0 会根据以下因素动态调整一笔交易的权重：

- 当前阶段是 `UNKNOWN`、`DISCOVERY` 还是 `MATURE`；
- 这笔交易是否和同一玩家在短时间内发生过反向回转；
- 最近 24 小时的流量是否过于集中在少数玩家；
- 交易玩家在这个物品上的历史参与天数是否过低。

其中最关键的一条约束是：**在 `UNKNOWN` 阶段，`SELL` 不能成为抬价证据。** 它可以帮助系统确认“这个物品至少不值那么高”，但不能仅靠持续卖出把一个新物品“卖成高价值”。这条规则是整个系统防首发操盘的基础。

如果系统判断当前操盘风险过高，而某笔交易又试图继续把价格往上推，这次上行更新会被直接冻结。

### 3. 市场为什么分阶段

EcoBrain 4.0 把物品的市场成熟度分成三个阶段：`UNKNOWN`、`DISCOVERY` 和 `MATURE`。

`UNKNOWN` 表示系统几乎没有可靠认识，这个阶段的特点是价差宽、容错大、偏保守。`DISCOVERY` 表示已经开始出现分散且可用的买方证据，系统愿意让价格逐步收敛。`MATURE` 则表示这个物品已经具备相对稳定的买家基础和交易深度，可以用更接近成熟市场的方式报价。

默认情况下，当一个物品在 7 天窗口内已经积累到至少 3 个独立买家、可信买量达到 16，且操盘分仍低于 `0.50` 时，它会从 `UNKNOWN` 进入 `DISCOVERY`。之后，如果独立买家达到 10、可信买量达到 64、不确定性收敛到 `sigma <= 0.35`，同时流量集中度和操盘分也都维持在安全区间，它才会进入 `MATURE`。反过来，如果一个成熟物品的稳定性恶化，它也会退回 `DISCOVERY`，而不是永久享受成熟市场待遇。

### 4. 系统如何形成买价和卖价

这一版不再输出单一价格，而是输出四个相关但不同的量：

- `mid`：统计意义上的价格中枢；
- `reservation_price`：考虑库存压力后的保留价格；
- `bid`：系统向玩家收购物品时的报价；
- `ask`：系统向玩家卖出物品时的报价。

可以把这个过程理解成两步。第一步，系统先根据当前的 `mu_log_price` 得到 `mid`。第二步，系统再看库存状态：如果真实库存偏低，`reservation_price` 会高于 `mid`；如果库存偏高，`reservation_price` 会低于 `mid`。在此基础上，系统再按照不确定性和操盘风险展开一个半价差 `half_spread`，最终形成 `bid` 和 `ask`。

因此，玩家实际看到的不是“这个物品值多少钱”这一个答案，而是“系统愿意以什么价收、以什么价卖”这两个带风险意识的答案。这样的结构比单点价格更适合真实交易场景，因为库存、风险和不确定性本来就不应该被压缩成一个数字。

### 5. 为什么要引入 `trusted_float` 和 `liquidity_depth`

传统系统市场容易犯的一个错误，是把 `physical_stock` 直接当作市场深度。问题在于，库存再大，如果这些库存并没有对应的真实交易活跃度，系统也不应该表现得像一个深不可测的大市场。

所以 EcoBrain 4.0 先引入 `trusted_float`，把可信流动性限制在“物理库存”和“近期可信交易活跃度推导出的上限”之间。然后再根据 `trusted_float` 计算 `liquidity_depth`，并让深度大致随 `sqrt(trusted_float)` 增长，同时受到阶段倍率的影响。

这个设计有两个直接好处：

- 它避免了“大宗材料库存明明已经堆到很多，但价格却像一潭死水”的问题。
- 它也避免了“库存表面上很多，其实交易证据很薄，却被系统误判成深市场”的问题。

在此基础上，大额买卖会沿着深度曲线产生滑点。也就是说，单次交易量越大，平均成交价越会沿着市场曲线偏移，而不是整笔都按同一个边际价格结算。

### 6. 反操盘逻辑具体在看什么

这套系统目前显式关注四类行为特征：

- 7 天内的独立买家数和独立卖家数；
- 24 小时内前两名玩家的流量占比；
- 基于短窗口反向交易计算出的回转率；
- 玩家在该物品上的历史参与天数。

这些特征最终会合成一个 `manipulation_score`。当这个分数过高时，系统会同时做几件事：阻止阶段晋级、放宽价差、降低证据权重，必要时直接冻结上行更新。这样做的目标不是“绝对识别恶意行为”，而是让市场在面对可疑流量时自动转入更保守的姿态。

### 7. 为什么还保留 SELL backstop

虽然这版系统的主定价器已经不是旧式 SELL 税模型，但 SELL backstop 仍然保留，作用从“决定价格”变成了“做最后一道保险”。

当玩家在短时间内向系统倾销超出当前可信深度的大量物品时，backstop 会额外拉开卖出侧的惩罚，防止系统被一次性大额卖盘直接打穿。它不负责告诉市场“这个物品值多少”，但负责在极端情况下保护市场不被冲垮。

## 适用范围与边界

这套设计最擅长的，是高频、可堆叠、可重复掉落、并且能持续积累分散买方证据的物品。例如原版高频材料、RPG 服中可重复成交的副本材料，或者那些虽然带 NBT、但交易活跃度足够高的标准化战利品。

它不承诺能很快学准所有长尾物品，尤其是：

- 只出现一两次的稀有收藏品；
- 精确 NBT 的单件装备；
- 每次掉落都显著变化、难以积累复用证据的自定义物品。

对这些物品，系统会有意保持更保守的姿态：更高的不确定性、更宽的价差，以及更慢的上行学习速度。换句话说，EcoBrain 4.0 的设计取向不是“让所有物品都迅速学出一个好看的价格”，而是“先避免被错误定价和被操盘，再在有证据时逐步收敛”。

## 总结

如果用一句话概括 EcoBrain 4.0，它不是一个“自动调价脚本”，而是一个面向游戏经济环境的统计型系统做市器。

它的核心贡献不在于给出一个永远正确的价格，而在于提供了一套更符合真实服务器生态的价格形成机制：新物品先保守进入市场，成熟物品再逐步收敛；真实分散需求可以推动价格学习，短期操盘则会被压低权重甚至冻结；库存会影响报价，但不会被简单等同于流动性。

相较于旧的单点价格逻辑，这一版更像是在维护一个“带置信度、带阶段、带风控”的市场状态。对于 Minecraft 服务器，尤其是 RPG 经济来说，这比单纯追求一个即时价格更重要，因为真正决定市场质量的，从来不只是价格本身，还有这个价格是如何形成的。
